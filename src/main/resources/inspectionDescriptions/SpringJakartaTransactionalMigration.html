Reports usage of jakarta.transaction.Transactional (or javax.transaction.Transactional) in Spring-managed code.

Spring's transaction management (enabled via @EnableTransactionManagement) only recognises its own org.springframework.transaction.annotation.Transactional. The Jakarta variant is silently ignored at runtime, so no proxy is created and the method executes without an actual transaction boundary.

The quick fix replaces the annotation with Spring's @Transactional and migrates Jakarta-specific attributes:

  • value = TxType.REQUIRES_NEW → propagation = Propagation.REQUIRES_NEW
  • rollbackOn → rollbackFor
  • dontRollbackOn → noRollbackFor
