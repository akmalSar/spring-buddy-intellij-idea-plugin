Reports a no-arg constructor call followed by a chain of setter calls on a class annotated with Lombok's @Builder, when the entire sequence can be collapsed into a single builder expression.

Replacing setter chains with the builder pattern removes intermediate mutable state, reduces the number of statements, and makes it immediately clear which fields are initialised and with what values.

Example:


B2bInvoiceVatDto dto = new B2bInvoiceVatDto();
dto.setId(feDto.getId());
dto.setHeadId(feDto.getHeadId());
dto.setVatAmount(feDto.getVatAmount());
dto.setVatRate(feDto.getVatRate());
dto.setVatGroup(feDto.getVatGroup());
dto.setVatCountry(feDto.getVatCountry().getId());
dto.setBaseAmount(feDto.getBaseAmount());
dto.setVatCalculationType(feDto.getVatCalculationType().getId());

After applying the quick-fix:


B2bInvoiceVatDto dto = B2bInvoiceVatDto.builder()
    .id(feDto.getId())
    .headId(feDto.getHeadId())
    .vatAmount(feDto.getVatAmount())
    .vatRate(feDto.getVatRate())
    .vatGroup(feDto.getVatGroup())
    .vatCountry(feDto.getVatCountry().getId())
    .baseAmount(feDto.getBaseAmount())
    .vatCalculationType(feDto.getVatCalculationType().getId())
    .build();

When is this triggered?

  • The variable is initialised with a no-arg constructor.
  • The constructed class is annotated with @Builder or lombok.Builder.
  • One or more consecutive variable.setXxx(...) calls follow the declaration in the same block.
  • Each setter call has exactly one argument (complex expressions and nested calls are preserved verbatim).

The inspection stops collecting setter calls at the first statement that is not a direct setter on the declared variable, so only the contiguous block is replaced. Statements that appear after an unrelated line are left untouched.
