Reports domain classes that depend on Spring Web, the Servlet API, JPA and persistence frameworks, or the infrastructure layer (code SB-ARCH-004, preset domainPurity).

Domain classes are those in the domain layer of .spring-buddy/architecture.json, or in any ..domain.. package when no layer is defined. Forbidden:

  • domain-no-web: org.springframework.web.., org.springframework.http.., jakarta.servlet.., javax.servlet..
  • domain-no-persistence ("style": "hexagonal" only): jakarta.persistence.., javax.persistence.., org.hibernate.., org.springframework.data.., org.springframework.jdbc.., org.springframework.orm..
  • domain-no-infrastructure: the infrastructure layer, when it is defined

The checks depend on the declared "style":

  • layered (default): the usual JHipster / Spring Initializr layout where the domain or entity package holds JPA entities. The preset is off unless configured explicitly, JPA types are allowed, and classes annotated @Entity, @Embeddable or @MappedSuperclass are never reported.
  • hexagonal: ports and adapters. The preset runs at WARNING by default and the domain must not know JPA either. A domain that knows HTTP or the ORM cannot be tested or reused without them. To accept selected types, use "domainPurityAllow": ["jakarta.persistence.Embeddable", "jakarta.persistence.Id"].

Set "presets": { "domainPurity": "error" } to block commits, or "off" to disable it.
