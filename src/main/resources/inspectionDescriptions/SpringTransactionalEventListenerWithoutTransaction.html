Reports @TransactionalEventListener methods that are not themselves transactional and are not inside a transactional class.

Transactional event listeners are bound to transaction phases. If the listener performs database work, making the transaction boundary explicit avoids accidental non-transactional writes and clarifies intent.

Add @Transactional when the listener performs transactional work, or use plain @EventListener if transaction phase semantics are not needed.

Use @Transactional(propagation = Propagation.REQUIRES_NEW) only when the listener work must commit independently from any surrounding transaction, for example audit/outbox-style writes. This changes semantics and can increase connection usage.
