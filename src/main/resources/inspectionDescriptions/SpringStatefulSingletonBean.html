Reports mutable instance fields in singleton Spring beans such as @Service or @Component classes.

Spring beans are singletons by default. Mutable per-request or per-operation state stored in the bean instance can be shared by multiple request threads and cause races or stale data.

Prefer method-local state, immutable fields, request/session-scoped components, or explicitly thread-safe state when sharing is intentional.

Quick-fix guidance:

  • Make field final: use when the field is dependency/configuration/object identity that should be assigned once and never replaced.
  • Mark field volatile: use only for a simple latest-value flag/reference where reads and writes are independent. It gives visibility, not atomic compound updates.
  • Convert field to AtomicReference: use for reference state that needs atomic replacement or compare-and-set style updates. It does not make the referenced object itself thread-safe.
