Reports incorrect usage of Lombok {@code @NonNull}.

@NonNull on a primitive field

Lombok's {@code @NonNull} adds a null-check in the generated constructor and setter. On a primitive field ({@code int}, {@code long}, {@code boolean}, etc.) this is meaningless because primitives can never be {@code null}. The annotation serves no purpose and adds visual noise. Remove it.


// Warning — primitives cannot be null
@NonNull
private int amount;

@NonNull and @Builder.Default on the same field

This combination causes a {@code NullPointerException} during construction. Lombok executes the null-check before applying the {@code @Builder.Default} value, so the field is still {@code null} at the moment of the check. Use one or the other, not both.


// NullPointerException at runtime
@Builder
public class Dto {
    @NonNull
    @Builder.Default
    private String status = "NEW";
}
// builder().build() throws NPE — null check fires before default
