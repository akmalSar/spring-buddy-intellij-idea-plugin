Reports {@code @Builder} or {@code @SuperBuilder} annotations that are either redundant (an explicit {@code builder()} static method already exists in the class) or unused (the annotated class has zero references anywhere in the project and no textual {@code ClassName.builder()} call sites).

Redundant @Builder

When a class already declares its own {@code builder()} method, the Lombok annotation serves no purpose because the hand-written method shadows the generated one. Removing the annotation cleans up the declaration without changing behaviour.

Example:


// Before
@Builder
public class InvoiceDto {
    private String invoiceDate;

    public static Builder builder() {
        return new Builder();
    }
}

After applying the quick-fix:


// After
public class InvoiceDto {
    private String invoiceDate;

    public static Builder builder() {
        return new Builder();
    }
}

Unused @Builder

When a concrete class carries {@code @Builder} but is never referenced in the project (neither via {@code new ClassName(...)} nor {@code ClassName.builder()}), the generated builder is guaranteed dead code. The inspection flags the annotation so it can be removed.

Abstract classes are skipped because subclasses may rely on the parent builder pattern.

The unused check uses a two-tier strategy:

  • First, it looks for resolved PSI references to the class (constructor calls, field declarations, type casts, etc.).
  • If none are found, it scans project source files for textual {@code ClassName.builder} or {@code ClassName::builder} patterns. This catches call sites where the synthetic {@code builder()} method does not exist in the PSI and therefore cannot be found by a standard reference search.

Quick-fix: Remove unused/redundant @Builder
