Detects manually defined methods that shadow Lombok-generated getters.

Manual method matching a Lombok getter signature

Lombok skips generating a getter for a field when a method with the same signature already exists in the class. This is by design, but it creates a fragile situation: if the manual method is later removed, Lombok will silently start generating the getter — potentially with different behaviour (the default {@code getX()} simply returns the field value).

Either keep the manual getter and remove the Lombok annotation from the field to make the dependency explicit, or remove the manual method and rely on Lombok's generation.


@Getter
public class InvoiceDto {
    private String invoiceDate;

    // Lombok skips generating getInvoiceDate() because this exists
    public String getInvoiceDate() {
        return invoiceDate != null ? invoiceDate : "N/A";
    }
    // If this method is removed, Lombok will auto-generate a plain getter
}
