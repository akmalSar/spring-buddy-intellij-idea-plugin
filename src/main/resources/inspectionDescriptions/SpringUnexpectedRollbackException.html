Caught RuntimeException from @Transactional call masks UnexpectedRollbackException

Reports catch blocks that swallow a RuntimeException from a call to a @Transactional bean method without re-throwing, while inside another @Transactional scope. The inner transaction is already marked rollback-only when the exception escapes, so even though the caller "handles" the error, Spring throws an UnexpectedRollbackException at commit time. Either re-throw the exception or set noRollbackFor on the inner transaction if the exception is intentional.
