Reports when a collection returned by a Spring Data repository or EntityManager query is immediately chained into an in-memory .stream().filter(), .sorted(), .skip(), or .limit() operation.

Fetching thousands of rows into JVM memory just to discard 90% of them in a Java stream wastes heap, CPU, and database throughput. Push the filtering to the database layer instead: write a custom @Query, use a derived query method (e.g. findByStatus(...)), or pass a Pageable/Specification to the existing repository method.
