Reports uses of a banned class, annotation or method from the bannedApis section of .spring-buddy/architecture.json outside the packages where it is allowed (code SB-ARCH-006).

Teams often route a risky or legacy API through one wrapper package (a clock abstraction instead of java.util.Date, a mail gateway instead of a raw client). Uses outside that package bypass the wrapper's policy: time zones, retries, auditing or tenant handling silently stop applying.

symbol is a fully-qualified type or annotation (java.util.Date) or a method written as Type#method (all overloads). The symbol is matched against the PSI-resolved target, so lookalike names and unresolved references are never reported. Banned types are reported once per file, at the import or the first use. Banned methods are reported at every call and method reference, including calls through subclasses that override the method. allowedIn accepts package patterns or layer names. Test sources are skipped unless includeTests is true.

The severity comes from each entry (error, warning, weak_warning, off). ERROR findings block the Spring Buddy pre-commit check. Fix the finding by calling the wrapper from the allowed package instead; fixHint names the replacement.

Example entry:

{ "id": "no-legacy-date", "symbol": "java.util.Date", "allowedIn": ["com.acme.support.time.."],
  "severity": "error", "message": "Use the Clock wrapper",
  "fixHint": "inject com.acme.support.time.Clock and use Instant" }
