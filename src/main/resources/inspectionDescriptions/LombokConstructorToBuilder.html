Reports constructor calls on classes annotated with Lombok's @Builder that can be replaced with the builder pattern.

Using the builder pattern instead of direct constructor calls improves readability, especially when a class has many fields, and makes it easier to understand which value is assigned to which field at the call site.

Example:


// Before
PaymentAcquirerInsertDto dto = new PaymentAcquirerInsertDto("visa", 100, true);

After applying the quick-fix:


// After
PaymentAcquirerInsertDto dto = PaymentAcquirerInsertDto.builder()
    .acquirer("visa")
    .amount(100)
    .active(true)
    .build();

When is this triggered?

  • The constructed class is annotated with @Builder or lombok.Builder.
  • The constructor call has one or more arguments.
  • All constructor parameter names can be mapped to fields on the class.

If the parameter names do not match the field names (e.g. the constructor was written by hand with different naming), the inspection will not trigger to avoid generating incorrect code.
