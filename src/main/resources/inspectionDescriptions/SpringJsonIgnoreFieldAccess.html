Reports access to @JsonIgnore'd properties on DTO parameters inside Spring-managed components (services, validators, event listeners, etc.).

When a DTO arrives in a Spring component through Jackson deserialization (e.g. from a controller @RequestBody), fields annotated with @JsonIgnore or listed in @JsonIgnoreProperties are null or default values. Accessing them silently produces incorrect data.

This inspection scans any Spring @Component, @Service, @Repository, @Controller, @RestController, or @Configuration class and flags every read access (field reference or getter call) on a method parameter whose declared type carries Jackson-excluded properties.

How to fix:

  • Remove the access if the property is not expected to be present.
  • Load the missing data from the database instead of relying on the DTO.
  • Remove @JsonIgnore if the field must be present in the DTO.

Note: fully-populated JPA entities that happen to carry @JsonIgnore for serialization purposes but are loaded from the database may trigger a false positive. Suppress the inspection for that method if you are certain the object was not deserialized.
