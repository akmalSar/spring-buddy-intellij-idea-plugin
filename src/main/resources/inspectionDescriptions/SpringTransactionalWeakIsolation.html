Weak/default isolation with multiple reads

Reports transactional methods that perform multiple reads while using default or weak isolation. Critical workflows can observe non-repeatable reads. Consider optimistic locking with @Version or stronger isolation such as REPEATABLE_READ or SERIALIZABLE.

Read-only transactions are excluded, as are methods that acquire a pessimistic lock through a repository method annotated with @Lock or a @Query containing FOR UPDATE, FOR NO KEY UPDATE or a PostgreSQL advisory lock (pg_advisory_xact_lock). The lock is also found through called methods, including helpers in other beans that run such SQL with JdbcTemplate, up to three calls deep. A method is also excluded when every non-test caller, including callers through an interface it implements, takes such a lock in the transaction it joins.
