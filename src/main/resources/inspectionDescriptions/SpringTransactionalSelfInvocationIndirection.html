Reports non-transactional methods that call another method in the same class, which eventually calls a @Transactional method, causing the transaction boundary to be bypassed through self-invocation indirection.

Spring AOP proxies only intercept calls that come through the proxy. When method A calls method B, and B calls @Transactional method C, all calls stay within the raw object — the proxy is never involved. The @Transactional advice on C is completely ignored. Refactor to call the transactional method from a separate bean, or make the initial entry point @Transactional.
