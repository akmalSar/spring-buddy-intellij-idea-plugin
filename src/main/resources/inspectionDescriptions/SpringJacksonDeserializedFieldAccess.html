Reports access to properties that are not available after Jackson deserialization of a @RequestBody or @Valid parameter in a Spring controller, including through chained getter navigation.

Jackson deserialization does not populate fields annotated with @JsonIgnore or listed in @JsonIgnoreProperties. When a controller method accesses such a field directly or via user.getAddress().getStreet() after deserialization it will read null or a default primitive value, which is a silent data bug.

When a class or parameter carries @JsonSerialize(as = SomeView.class), only the properties exposed by that view interface (plus id) are guaranteed to be available on the deserialized instance. Accessing any other property may trigger a runtime IllegalStateException when the object is a proxy-backed view guard.

How to fix:

  • Remove the field access if it is not needed.
  • Use a DTO that only contains the properties you actually need.
  • Remove @JsonIgnore if the field must be deserialized.
