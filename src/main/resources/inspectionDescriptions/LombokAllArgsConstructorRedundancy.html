Reports @AllArgsConstructor annotations that are redundant because an explicit all-args constructor already exists and is never used, and removing the annotation would not break Spring DI or final-field initialization.

Lombok's @AllArgsConstructor generates a constructor at compile time. If a hand-written constructor with the same signature already exists and no code calls it directly, the annotation serves no purpose and can safely be removed to reduce visual noise.

Example:


// Before
@AllArgsConstructor
public class PaymentDto {
    private String acquirer;
    private int amount;

    public PaymentDto(String acquirer, int amount) {
        this.acquirer = acquirer;
        this.amount = amount;
    }
}

After applying the quick-fix:


// After
public class PaymentDto {
    private String acquirer;
    private int amount;

    public PaymentDto(String acquirer, int amount) {
        this.acquirer = acquirer;
        this.amount = amount;
    }
}

When is this triggered?

  • The class is annotated with @AllArgsConstructor or lombok.AllArgsConstructor.
  • An explicit constructor with the same parameter count as instance fields exists.
  • The explicit constructor has zero usages in the project.
  • The class is not a Spring-managed bean (e.g. @Component, @Service, @Controller, etc.).
  • The class is not annotated with @ConfigurationProperties.
  • The class has no uninitialized final fields (which would require the generated constructor for legal instantiation).
