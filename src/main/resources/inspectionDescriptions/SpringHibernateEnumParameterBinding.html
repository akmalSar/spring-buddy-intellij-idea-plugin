Reports setParameter bindings that pass a String or number to a named parameter that the query compares against an enum-typed path (for example an @Enumerated(EnumType.STRING) field). This is a runtime-breaking error: Hibernate 6 fails the query when it executes.

Hibernate 6 validates the parameter binding type when a query executes. Binding a String to an enum path fails at runtime with Argument [W] of type [java.lang.String] did not match parameter type [TransferState]. Hibernate 5 silently converted the value, so migrated applications typically only discover this in production. 

// broken: transferStatus is an enum field, the bound value is a String
em.createQuery("SELECT a FROM " + clazz + " a WHERE a.transferStatus != :transferStatus")
  .setParameter("transferStatus", "W")              // fails at runtime

// fixed: bind the enum constant
em.createQuery("SELECT a FROM " + clazz + " a WHERE a.transferStatus != :transferStatus")
  .setParameter("transferStatus", TransferState.W)

The inspection walks the fluent createQuery(...).setParameter(...) call chain and resolves every compared path against the entity model. The root entity is taken from the result class argument, or from the entity name after FROM. When the entity name is built dynamically, the compared field is resolved by name across all JPA entities of the project and reported only when every matching field has the same enum type. When the bound value is a String literal that names an enum constant, a quick fix replaces it with that constant. Native queries are not checked.
