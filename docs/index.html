Why It Is Unique

Most tools see syntax. Spring Buddy models Spring consequences.

The plugin focuses on bugs caused by framework behavior that is legal Java but wrong Spring: proxy bypasses, transaction boundaries, lifecycle timing, repository semantics, lazy loading, Jackson DTO traps, Lombok-generated method hazards, test false positives, and style drift.

Spring proxy awareness

Flags private, final, static, self-invoked, CGLIB-blocked, constructor-triggered, async, and interface transaction patterns that Spring AOP cannot apply as expected.

Runtime risk, editor timing

Surfaces production-class issues while the file is open: missing transactions, ignored annotations, broken Mockito calls, and lifecycle traps.

Developer-safe fixes

Adds targeted fixes only when the edit is unambiguous: add @Transactional, remove proxy-blocking modifiers, add EnumType.STRING, add auditing listeners, wrap Streams, migrate assertions, and repair Lombok defaults.

Runtime flow diagrams

Shows clickable inlay hints and tool windows for transaction paths, Ghost Saves, transaction-boundary escapes, lazy-init risks, self-invocation, SQL injection flow, bag problems, and N+1 paths.

Inter-procedural taint analysis

DataFlow engine tracks detached entities and tainted strings through aliases, Optional unwraps, casts, ternaries, loops, stream lambdas, and helper methods — finding Ghost Saves, SQL injection, lazy-init leaks, boundary escapes, and N+1 paths across call boundaries.

Test ecosystem support

Understands AssertJ, Mockito, MockMvc, ArchUnit, and helper-method assertion patterns instead of applying a single naive assertion rule.

Bundled inspection pass

Runs Spring Buddy or Lombok Buddy after large refactors, generated code changes, or AI-assisted rewrites to catch hidden framework regressions.

How The Analysis Runs

From code edit to actionable feedback.

Spring Buddy plugs into IntelliJ's inspection infrastructure. Each inspection receives structured Java PSI, resolves relevant symbols, avoids brittle name guessing where possible, applies Spring-specific rules, and reports precise problems back to the editor.

1

Developer edits Java

Spring services, controllers, repositories, tests, configuration, and entities.

2

IDE builds PSI

IntelliJ exposes syntax nodes, annotations, modifiers, calls, classes, and references.

3

Rules inspect nodes

Local inspections walk methods, fields, annotations, and call chains. DataFlow engine seeds taint, propagates aliases, and follows inter-procedural boundaries.

4

Spring semantics added

Rules interpret proxy limits, transaction propagation, persistence access, lifecycle order, taint flow, and test intent.

5

Feedback appears

Errors, warnings, quick fixes, tooltips, inlay hints, and runner output guide the developer.

The key difference: the warning is connected to the Spring behavior that will happen at runtime, not only to how the Java code looks.

Concrete Example

It catches valid Java that Spring will not execute the way it looks.

A same-class call to a transactional method looks correct in Java, but bypasses the Spring proxy. Final classes, private methods, @PostConstruct, and missing @Transactional boundaries fail for the same reason: Spring behavior is hidden behind framework rules.

What the developer sees

Error or warning on the exact call, annotation, method, or class, plus a quick fix when Spring Buddy can apply one safely.

This is unique because the plugin teaches the framework model while identifying the bug.

Feedback Types

Different problems need different IDE feedback.

Spring Buddy does not force every finding into one format. It uses errors for definite runtime breakage, warnings for likely design risks, quick fixes for safe edits, inlay hints for runtime explanation, and runner actions for broad sweeps.

Errors

Mark definite runtime breakage: ignored proxy advice, @Transactional on private/final/static methods, self-invocation, readOnly transactions with writes, swallowed exceptions, unclosed repository Streams, missing no-arg constructors, cascade delete risks, stale persistence context, SQL injection via @Query concatenation and taint flow, @Async without Executor, Jackson lazy serialization, hardcoded secrets, Jakarta @Transactional migration, transaction boundary escape, LazyInitializationException prediction, and read-only entity mutation.

Warnings

Flag likely design risks and style drift: import ordering, modifier placement, method visibility, test naming, TODO/FIXME without tickets, collection return nulls, @RequestMapping without HTTP method, fixedRate without initialDelay, findAll without Pageable, unvalidated MultipartFile uploads, mutable @Configuration state, Hibernate 6 migration hazards, and Ghost Save (detached entity mutation).

Quick Fixes

Add @Transactional, choose REQUIRES_NEW, remove final, add EnumType.STRING, add auditing listeners, add mappedBy, wrap Stream in try-with-resources, convert to contextual orElseThrow, or replace string concatenation with parameter placeholders.

Inlay Hints + Flow Views

Show transaction behavior inline and open navigable flow diagrams for transaction paths, Ghost Save, boundary escape, lazy-init, self-invocation, SQL injection, bag problem, and N+1 findings.

After Big Refactors

Especially useful after broad AI-assisted rewrites.

Large refactors can keep Java compiling while silently changing Spring behavior. Spring Buddy gives you a second pass focused on the things compilers and ordinary linters miss.

Proxy Semantics

Catches final classes, final/private/static advised methods, self-invocation, and ignored @PostConstruct transactions introduced during cleanup.

Repository Semantics

Finds @Modifying without @Transactional, derived query explosions, Optional.get() without context, and projection methods that force full entity loads.

Persistence Drift

Flags enum ordinal mappings, missing auditing listeners, @OneToMany join-table surprises, N+1 lazy access, OSIV risks, and Ghost Saves from detached entity mutations introduced by AI rewrites.

Test Behavior

Recognizes real assertions after test rewrites and catches @MockBean context fragmentation that makes suites slower after refactors.

Concurrency Regressions

Highlights singleton mutable state, shared caches, @Async writes, and suggests final, volatile, AtomicReference, or ConcurrentHashMap where appropriate.
